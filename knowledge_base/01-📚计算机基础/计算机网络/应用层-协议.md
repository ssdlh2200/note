## HTTP
### 基本概念
HTTP协议(Hypertext Transfer Protocol，超文本传输协议)，是一个客户端请求和响应的标准协议，这个协议详细规定了浏览器和万维网服务器之间互相通信的规则。用户输入地址和端口号之后就可以从服务器上取得所需要的网页信息。
通信规则规定了客户端发送给服务器的内容格式，也规定了服务器发送给客户端的内容格式。
- 客户端发送给服务器的格式叫"请求协议"
- 服务器发送给客户端的格式叫"响应协议”
+ 浏览器中书写格式
    - http://127.0.0.1:8080/myweb?name=zhangsan
**HTTP协议的特点**
1. 内容兼容：HTTP允许传输任意类型的数据对象。传输的类型由ContentType加以标记。
2. <font color="#d83931"><b>无连接：无连接是表示每次连接只处理一个请求。服务器处理完客户的请求，并收到客户的应答后，即断开连接。采用这种方式可以节省传输时间。</b></font>
    - HTTP1.1版本后支持长连接。通过这种连接，就有可能在建立一个TCP连接后，发送请求并得到回应，然后发送更多的请求并得到更多的回应，通过把建立和释放TCP连接的开销分摊到多个请求上，则对于每个请求而言，由于TCP而造成的相对开销被大大地降低了。而且，还可以发送流水线请求，也就是说在发送请求1之后的回应到来之前就可以发送请求2也可以认为，一次连接发送多个请求，由客户机确认是否关闭连接，而服务器会认为这些请求分别来自不同的客户端。
3. 无状态：无状态指的是在请求和响应的过程中，服务端不会保存关于客户端的任何状态信息。对于每个请求，服务端都将其视为独立的，不会与之前或之后的请求有任何关联。这意味着服务端不会依赖或记忆之前的请求来处理当前的请求。
### URL
HTTP(超文本传输协议)是一个基于请求与响应模式的、应用层的协议，常基于TCP的连接方式，绝大多数的Web开发，都是构建在HTTP协议之上的Web应用。

HTTP URL（URL是一种特殊类型的URI，包含了用于查找某个资源的足够的信息的格式如下：
`http` :// `host`:`port` / `abs_path`

+ http：表示要通过HTTP协议来定位网络资源
+ host：表示合法的Internet主机域名或者IP地址
+ port：指定一个端口号，为空则使用缺省端口80
+ abs_path：指定请求资源的URI。如果URL中没有给出abs_path，那么当它作为请求URI时，必须以"/"的形式给出，通常这个工作浏览器自动帮我们完成。**？？**

#### 常见的响应码
+ 500 内部服务器错误

Internal Server Error 500内部服务器错误，服务器遇到未知无法解决的问题。

一般情况下，出现500响应状态的原因有很多种，但是主要的是“程序代码和服务器配置”两个问题。相对于代码而言，就是对站点进行升级，网页改版，新增加了一些常用的插件。就比如WordPress插件的版本可能就需要更高版本的PHP才能兼容。而相对服务器而言的话，更多的是在系统版本升级导致，就比如最开始使用的是Windows Server 2003，后期想要升级2008、2012等版本的时候配置稍有不慎就会导致Internal Server Error 500。

+ 404 请求错误

Not Found 404 错误请求，因发送的请求语法错误,服务器无法正常读取。

相信绝大多数的人都见过404的状态码，当用户试图请求Web服务器上一个不存在的资源时，就会触发Not Found404。出现404状态码可能是链接失效导致，也有可能是URL拼写错误，还有可能是因为Web服务器将所请求的资源移到了其他的地方。一般的网站都会设置自定义页面以防链接失效所产生不良的影响。

+ 403 禁止访问

Forbidden 403 禁止访问，客户端没有权利访问所请求内容,服务器拒绝本次请求。

状态码403通常代表客户端错误，是指的服务器端有能力处理该请求，但是拒绝授权访问。这个状态码类似于401，但是进入该状态后不能再继续进行验证，该访问是长期禁止的，并且与应用逻辑密切相关，比如密码不正确等。

+ 200 请求成功

200 OK 请求成功，表示已经请求成功，默认情况下的状态码为200的响应就可以被缓存了。

### HTTP1.1
HTTP/1.0中，默认情况下，每次发送完HTTP请求后，TCP连接会被断开。这是为了支持早期的Web应用，其中每个请求都是独立的，并且服务器不期望客户端在短时间内发送多个请求。然而，这种方式在每次请求时都需要建立和断开TCP连接，对于性能来说并不高效。

HTTP/1.1中，引入了持久连接（persistent connections）（Connection：keep-alive）的概念。默认情况下，HTTP/1.1假设连接是持久的，即发送完一个请求后，TCP连接不会立即断开，而是保持打开状态，以便后续的请求可以继续使用相同的连接。这可以减少建立和断开TCP连接的开销，提高性能。**<font style="color:#DF2A3F;">HTTP1.1服务端无法向客户端主动推送数据</font>**

需要注意的是，即使使用HTTP/1.1，服务器也可能在响应头中使用Connection: close来指示客户端在发送完请求后断开连接。同样，客户端也可以在请求头中使用Connection: close来请求服务器在响应后断开连接。

也可以设置keep-alive: timemot=60来设置超时时间

:::danger
1. <font style="color:rgb(51, 51, 51);">持久连接可以说明http1.1是有状态的吗？</font>
    - <font style="color:rgb(51, 51, 51);">持久连接仅仅是在物理层面复用了TCP连接，使得多个HTTP请求可以在同一个TCP连接上连续发送，而不必每次请求都重新建立连接。</font>
    - <font style="color:rgb(51, 51, 51);">因此，长连接只是提高了通信效率，并不意味着HTTP协议变成了有状态的。如果需要实现状态管理，通常需要使用其他技术，如Cookie或Session等。</font>
2. 虽然TCP支持全双工，但是HTTP1.1仍然是只支持半双工。同一时间内客户端和服务器只能有一方发送数据

:::

### 长轮询和短轮询
+ 短轮询：在建立TCP连接后，每隔很短段时间（大概2,3秒）客户端就发送一个请求去获取服务器的最新数据。
+ 长轮询：在建立TCP连接后，发起一个请求在较长时间（设置HTTP请求超时时间为30s）内等待服务器返回数据的机制就是长轮询。

### HTTP状态管理
#### cookie，session
+ [https://en.wikipedia.org/wiki/HTTP_cookie#Implementation](https://en.wikipedia.org/wiki/HTTP_cookie#Implementation)

**cookie**和**session**解决了HTTP协议无法记录用户状态的机制

HTTP头中的cookie

```java
Cookie: session_id=1234567890ABCDEF; user_id=john_doe; auth_token=XYZ123
```

**Cookie：**浏览器用来保存服务端数据的一种机制，当我们通过浏览器去进行网页访问的时候，服务器可以把某一些状态数据以key-value写入到cookie中，存储到客户端中。在下一次客户端访问浏览器的时候，客户端可以携带这些状态数据发送到服务器端，服务端可以根据cookie里面的内容识别使用者。

**Session：**表示一个会话，是服务器端的一个容器对象，不同的语言具体实现有差别。

+ **Java语言**

[Servlet](https://www.yuque.com/ssdlh-kbjpw/ru064f/zpshyfxexq9nl2m6#OCWME)

**区别：**

1. **存储位置**
+ <font style="color:rgb(51, 51, 51);">Cookie存储在客户端（用户的浏览器）上。这意味着用户可以在不同的设备或浏览器之间共享Cookie，但也可能带来安全风险，因为其他人可以访问和分析存储在本地的Cookie。（Session ID通常存储在Cookie中，这样服务器就可以通过读取客户端发送的Cookie来识别会话。）</font>
+ <font style="color:rgb(51, 51, 51);">Session则存储在服务器上。客户端每次请求时，服务器会根据Session ID查找对应的Session数据。这种方式更安全，因为敏感信息不会存储在客户端。</font>
2. **<font style="color:rgb(51, 51, 51);">数据类型和大小限制</font>**
+ <font style="color:rgb(51, 51, 51);">Cookie只能保存字符串类型的数据，且单个Cookie的大小有限制（通常为4KB）。此外，很多浏览器还限制了一个站点最多可以保存的Cookie数量。</font>
+ <font style="color:rgb(51, 51, 51);">Session没有数据类型的限制，可以保存任何类型的对象。同时，Session也没有数据大小限制，可以存储大量信息。</font>
3. **安全性**
+ <font style="color:rgb(51, 51, 51);">由于Cookie存储在客户端，因此相对不那么安全。恶意用户或软件可能能够访问、修改或删除Cookie，导致安全漏洞。</font>
+ <font style="color:rgb(51, 51, 51);">Session存储在服务器上，因此更为安全。但需要注意的是，如果Session ID被窃取，攻击者可能能够假冒其他用户的身份。</font>
4. **生命周期**
+ <font style="color:rgb(51, 51, 51);">Cookie的生命周期由设置时的Expires/Max-Age属性决定，可以长期保存在客户端。</font>
+ <font style="color:rgb(51, 51, 51);">Session的生命周期则依赖于服务器端的设置和客户端的会话状态。当用户关闭浏览器或会话超时时，Session通常会结束。</font>
5. **路径问题**
+ <font style="color:rgb(51, 51, 51);">如果Cookie中设置了路径参数，那么同一个网站中不同路径下的Cookie互相是访问不到的。</font>
+ <font style="color:rgb(51, 51, 51);">Session则不能区分路径，同一个用户在访问一个网站期间，所有的Session在任何一个地方都可以访问到。</font>

<font style="color:rgb(51, 51, 51);">单独说明：</font>

<font style="color:rgb(25, 27, 31);">Cookie中存放的信息包含cookie本身属性和用户自定义属性，一个cookie只能包含一个自定义键/值对。Cookie本身属性有”Comment” 、”Domain”、”Max-Age”、”Path”、”Secure”、”Version”。</font>

**<font style="color:rgb(25, 27, 31);">以下是一些常见的在session中存放的数据类型：</font>**

+ <font style="color:rgb(25, 27, 31);">用户身份信息：例如用户名、用户ID、电子邮件地址等。这些信息用于识别用户身份，并在用户进行后续请求时验证其身份。</font>
+ <font style="color:rgb(25, 27, 31);">登录状态：用于表示用户是否已登录，以及登录的时间等信息。这有助于应用程序确定用户是否需要进行身份验证或重定向到登录页面。</font>
+ <font style="color:rgb(25, 27, 31);">权限和角色：存储用户的权限和角色信息，以便应用程序根据用户的权限来限制或允许访问特定的资源或功能。</font>
+ <font style="color:rgb(25, 27, 31);">会话令牌或密钥：用于在客户端和服务端之间建立安全的会话连接。这些令牌通常用于验证用户的身份和授权请求。</font>
+ <font style="color:rgb(25, 27, 31);">购物车数据：在电子商务网站中，session可以用于存储用户的购物车信息，包括商品ID、数量等。</font>
+ <font style="color:rgb(25, 27, 31);">临时数据：任何需要在用户会话期间保留的临时数据都可以存储在session中。这些数据可能在用户的多个请求之间共享，但在会话结束时不再需要。</font>

### 预检请求/CORS跨域
#### 介绍
+ [https://developer.mozilla.org/zh-CN/docs/Web/HTTP/CORS](https://developer.mozilla.org/zh-CN/docs/Web/HTTP/CORS)

浏览器有一个同源机制指的是**协议**，**域名**，**端口**都相同，如果任意一向不一致就是不同源。网页的URL和调用接口的URL不是同一个地方的，浏览器觉得有风险会拦截该数据

|  URL1 | URL 2 | 是否同源 | 原因 |
| --- | --- | --- | --- |
| https://www.example.com | https://www.example.com | | 协议、域名、端口完全相同 |
| https:/www.example.com | http://www.example.com | | 协议不同 |
| https:/www.example.com | https://api.example.com | | 域名不同 |
| https://www.example.com | https://www.example.com:8080 | 否 | 端口不同 |


#### 详解CORS
如果在服务端对于不是同一个域名下的请求，没有做同意处理

+ 如果是简单请求，则会直接返回服务端设定的处理，浏览器不显示
+ 如果是复杂请求，在禁止预检请求后，浏览器会禁止发送第二个请求（防止钓鱼复杂请求携带数据，去请求真正的数据）

不会触发预检请求的代码

public class HttpServer8081 {
    public static void main(String[] args) {
        new Thread(() -> m0(8081)).start();
    }
    private static void m0(int port) {
        new ServerBootstrap().group(new NioEventLoopGroup(), new NioEventLoopGroup())
                .channel(NioServerSocketChannel.class)
                .childHandler(new ChannelInitializer<NioSocketChannel>() {
                    @Override
                    protected void initChannel(NioSocketChannel ch) throws Exception {
                        ch.pipeline()
                                .addLast(new LoggingHandler(LogLevel.DEBUG))
                                .addLast(new HttpServerCodec())
                                .addLast(new HttpObjectAggregator(65535));


                        CorsConfig corsConfig = CorsConfigBuilder
                                .forOrigin("http://localhost:8080")
                                .allowedRequestHeaders("ssdlh-head-key")
                                .allowedRequestMethods(HttpMethod.GET, HttpMethod.POST)
                                .build();
                        ch.pipeline().addLast(new CorsHandler(corsConfig));


                        ch.pipeline()
                                .addLast(new SimpleChannelInboundHandler<HttpRequest>() {
                                    @Override
                                    protected void channelRead0(ChannelHandlerContext ctx, HttpRequest msg) throws Exception {
                                        byte[] res = "<h1>hello</h1>".getBytes();

                                        DefaultFullHttpResponse response = new DefaultFullHttpResponse(msg.protocolVersion(), HttpResponseStatus.OK);
                                        DefaultCookie cookie = new DefaultCookie("ssdlh-key", "ssdlh-value");
                                        response.headers().set(HttpHeaderNames.SET_COOKIE, ServerCookieEncoder.STRICT.encode(cookie));
                                        response.headers().setInt(HttpHeaderNames.CONTENT_LENGTH, res.length);
                                        response.content().writeBytes(res);
                                        ctx.writeAndFlush(response);
                                    }
                                });
                    }
                })
                .bind(new InetSocketAddress("localhost", port));
        System.out.println("启动完毕" + port);
    }
}

## Websocket
### websocket简介
+ [https://www.bilibili.com/video/BV1684y1k7VP](https://www.bilibili.com/video/BV1684y1k7VP)
+ [https://www.cnblogs.com/jiujuan/p/16174566.html](https://www.cnblogs.com/jiujuan/p/16174566.html)

浏览器在客户端和服务端建立通信后，都统一使用HTTP先进行第一次通信

+ 如果是普通的HTTP请求，则后续仍然使用HTTP协议
+ 如果想要websocket协议，则需要带上一些特殊的header头
    - connection: Upgrade，想要升级协议
    - Upgrade: websocket，想要升级的协议为websocket
    - Sec-WebSocket-Key: Base64编码

![](https://cdn.nlark.com/yuque/0/2024/png/33704534/1725697382112-9a81f81c-905b-4941-990c-1a765664c624.png)

![](https://cdn.nlark.com/yuque/0/2024/png/33704534/1725697403682-46a8dc15-9958-4a48-b300-87269a8d3eb9.png)

在 `ws://localhost:8895/ws` 中的两个 `ws` 表示不同的内容：

1. **前面的 **`**ws**`：这是 WebSocket 协议的前缀。类似于 HTTP 和 HTTPS，WebSocket 协议也有其前缀。`ws://` 表示不加密的 WebSocket 连接，类似于 `http://`。还有一个 `wss://`，表示加密的 WebSocket 连接，类似于 `https://`。
2. **后面的 **`**/ws**`：这是 WebSocket 服务器上的一个路径。它类似于 HTTP URL 中的路径部分。在这个例子中，`/ws` 是服务器的某个具体的端点（endpoint），客户端将会通过这个端点与 WebSocket 服务器建立连接。

总结来说，`ws://localhost:8895/ws` 是一个完整的 WebSocket URL，表示客户端要连接到本地的 WebSocket 服务器（`localhost`），端口为 8895，路径为 `/ws`。

### ping/pong帧格式
**Ping 帧报文头（无负载）**

+ **FIN**: 通常为 `1`，表示这是一个完整的帧。
+ **RSV1, RSV2, RSV3**: 通常为 `0`。
+ **Opcode**: `0x9`（表示这是一个 `Ping` 帧）。
+ **Mask**: 通常为 `0`（`Ping` 帧的负载通常不需要掩码）。
+ **Payload length**: 可选负载长度，最大为 125 字节（超过 125 字节的负载长度使用额外的长度字段）。

```java
+---------------+----------+---+---------------------------------+
| F | R | R | R | opencode | M | Payload Length  | Payload Data  |
| 1 | 0 | 0 | 0 |   1001   | 0 |       00        |     (none)    |
+---------------+----------+---+---------------------------------+

如果每四个字节一统计，那么 
1000 = 16进制8
1001 = 16进制9
```

![](https://cdn.nlark.com/yuque/0/2024/png/33704534/1726136965269-d299772e-08e9-4fd6-abfd-5c10676179cb.png)

**Pong 帧报文头（有负载）**

+ **FIN: **`1`
+ **RSV1, RSV2, RSV3: **`000`
+ **Opcode: **`**1010**`**（十六进制为 **`0xA`**）**

```java
+---------------+-------------+---+---------------------------------+
| F | R | R | R |  opencode   | M | Payload Length  | Payload Data  |
| 1 | 0 | 0 | 0 |    1010     | 0 |       00        |     (none)    |
+---------------+-------------+---+---------------------------------+

如果每四个字节一统计，那么 
1000 = 16进制8
1010 = 16进制A
```
